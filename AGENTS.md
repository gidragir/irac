# irac — инструкции для ИИ-агентов

Библиотека OneScript для администрирования кластера серверов 1С:Предприятие 8 через утилиту `rac`
(локально, через `Команда`) или HTTP-сервис hiRAC (если вместо версии/пути передан `http(s)://…`, через `1connector`).
Публичный API — объектная модель `УправлениеКластером1С → Кластеры → Кластер → ИнформационныеБазы/Сеансы/…` (см. `readme.md`).
Кодовая база и коммиты — на русском. Главный потребитель — vanessa-runner (`vrunner cluster …`).

## Устройство

| Путь | Что там |
|---|---|
| `src/Макеты/ТипыОбъектовКластера.json` | **описание всех типов объектов**: свойства (рус. имя → `ИмяРАК`, `Тип`, `Использование`, `ПоУмолчанию`) и команды rac (`ИмяРАК`, `ПараметрыКоманды`, авторизация). Большинство доработок — правка этого файла |
| `src/Макеты/Перечисления.json` | значения перечислений rac (`on/off`, режимы и т. п.) |
| `src/Модули/ТипыОбъектовКластера.os` | загрузка JSON-описаний |
| `src/Модули/Служебный.os` | лог, авторизация, `РазобратьВыводКоманды` (разбор `ключ : значение`, блоки через пустую строку) |
| `src/Классы/КомандыОбъекта.os` | сборка командной строки rac по описанию |
| `src/Классы/ИсполнительКоманд.os` | запуск rac / hiRAC, кодировка `RAC_ENCODING` (UTF8/OEM/ANSI) |
| `src/Классы/<Коллекция>.os` + `<Объект>.os` | коллекции (`Сеансы`) и элементы (`Сеанс`); общие `ОбъектыКластера`/`ОбъектКластера` |
| `lib.config` **и** `src/lib.config` | два реестра классов/модулей: корневой — для установленного пакета, `src/` — для `#Использовать "../src"` в тестах. Новый класс — в **оба** |
| `doc/rac.*.txt` | справка `rac help <режим>`: эталон имён полей и параметров |
| `tests/irac-test.os` + `tests/fixtures/` | тесты 1testrunner на записанном выводе rac |
| `features/` | BDD (1bdd) против живого кластера в docker (`Jenkinsfile`) |

## Окружение (Windows, PowerShell) — проверено

```powershell
opm install -l --dev                                          # один раз, в oscript_modules (в .gitignore)
chcp 65001 > $null
$env:OSCRIPT_CONFIG = "lib.additional=$PWD\oscript_modules"   # без этого: {Библиотека не найдена: '1testrunner'}
oscript tasks/test.os                                         # все тесты, ~2 с, «45 пройдено… Зеленая полоса»
.\oscript_modules\bin\1testrunner.bat -run .\tests\irac-test.os   # то же для одного файла
oscript tasks/coverage.os                                     # тесты + coverage/genericCoverage.xml
```

Режим задаёт `tests/fixtures/ПараметрыТестирования.ПоУмолчанию.txt` (`ЭтоСерверСборок = true`): `ИсполнительКоманд`
подменяется моком moskito, и rac не вызывается. Для живого кластера положи рядом `ПараметрыТестирования.txt`
(в `.gitignore`) с `ЭтоСерверСборок = false` и своими адресами и паролями. Этот файл никогда не коммить.

## Правила

- **Не запускай один тест по имени** (`-run file ТестДолжен_X`): моки накапливаются от теста к тесту, и одиночный тест падает в `Сеансы.Получить`. Прогоняй файл целиком.
- Новый тест-метод нужно добавить в `ПолучитьСписокТестов` (1testrunner без него тест не увидит), иначе число «Тестов пройдено» не вырастет.
- Совместимость: `packagedef` → `.ВерсияСреды("1.6.0")`, и библиотека работает в vanessa-runner на OneScript 2.x. Не используй синтаксис и API только одной ветки.
- Шапка файлов — лицензия MPL 2.0 (скопируй из соседнего файла), `*.os` — UTF-8, CRLF.
- Коммиты по-русски, часто с префиксом conventional: `fix: …`, `feat: …`, `refactor: …`, `test: …`, `ci: …`, `docs: …`.
- Ветки и релизы: git-flow (`develop`, `release/v.X.Y.Z`, теги `v.X.Y.Z`). `origin` — форк gidragir, `upstream` — ArKuznetsov. PR — в `upstream/develop`. Версия — `packagedef` `.Версия(...)`.
- Изменение публичного API (методы `readme.md`) ломает vanessa-runner. Проверяй там (см. ниже).

## Известные ловушки

- **OneScript 2.2.0**: `ПотокВывода.Прочитать()` отдаёт лишний перевод строки на каждый кусок, и записи rac рвутся. vanessa-runner держит кластерные e2e на 2.1.0. Правки `РазобратьВыводКоманды` проверяй выводом с несколькими пустыми строками подряд.
- В выводе rac `name`, `descr`, `application` приходят в кавычках (`УбратьКавычки`). Числа и даты приводятся только при `"Тип": "Число"`/`"Дата"` в описании.
- `rac` ищется через `v8find` по маске версии. Кодировка вывода на Windows часто требует `RAC_ENCODING=OEM`.
- `rac infobase summary list` (8.3.25) завершает вывод **двумя** пустыми строками. До `c739eff` `РазобратьВыводКоманды` добавлял из них пустое `Соответствие`. `ИнформационнаяБаза` из него выходит из `ПриСозданииОбъекта` раньше времени (`ПараметрыОбъекта = Неопределено`), и отбор по имени (`Получить(..., НеОбновлять)`) падает в `ИнформационнаяБаза.os:473` «Значение не является значением объектного типа». В vrunner так падает `cluster jobs lock`.
- Фиксы `c739eff` (пустые строки) и `9537ba1` (полный путь к rac) сделаны после тега `v.1.4.0`, но `packagedef` по-прежнему `1.4.0`. Хаб отдаёт 1.4.0 без них, а `opm` не видит обновления. Свой пакет собирай `opm build --out <каталог> .` (ключ `--out`, а не `-out`) и ставь с `-f`.
- Наличие фикса `c739eff` проверяй по контексту внутри цикла (за `МассивРезультатов.Добавить(Описание);` следует `Описание = Новый Соответствие();`) или по хэшу файла. Строка `Если ЗначениеЗаполнено(Описание) Тогда` есть и в старой версии, после цикла.
- Без `9537ba1` передать в `УправлениеКластером1С` полный путь к `rac.exe` нельзя: падает `ИсполнительКоманд.os:122` «Нельзя установить несуществующий путь к утилите RAC». Передавай версию платформы.

## Скиллы

- `extending-irac-rac-objects` — новое поле, команда или параметр rac, новый тип объекта кластера.
- Проверка локальной irac в vanessa-runner — скилл `using-local-irac-in-vanessa-runner` в репозитории vanessa-runner.
